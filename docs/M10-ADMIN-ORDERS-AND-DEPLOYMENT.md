# M10 — Admin order/payment management and hosting preparation

## Included

- Authenticated `GET /api/admin/orders` with pagination and order/payment status filters.
- Authenticated `GET /api/admin/orders/:id` with immutable order item snapshots and Paystack transaction history.
- Authenticated `PATCH /api/admin/orders/:id/status` for fulfilment state only.
- Dashboard Orders & Payments panel with filtering, paging, order detail, payment attempt history, and status updates.
- Payment status is intentionally read-only in the dashboard. Only verified Paystack processing can confirm payment. Paid orders cannot be cancelled from the dashboard; refund handling must happen through the gateway and a separately verified process.
- Exact-origin CORS support for separate frontend/backend hosting; configurable session cookie SameSite mode.
- `render.yaml` blueprint, Vercel static frontend config, and GitHub Actions backend syntax checks.

## Database prerequisite

Apply `backend/supabase/migrations/002_payment_foundation.sql` to the target Supabase project before testing order APIs. Do not run a migration against production without a backup and review.

## GitHub repository layout

Keep one monorepo with `frontend/`, `backend/`, `docs/`, `.github/`, and `render.yaml` at repository root. Commit `.env.example`, never `.env`, real keys, database passwords, or Paystack secrets.

## Render backend

Create a Render Blueprint from the repository root and review `render.yaml`, or create a Web Service manually:

- Root Directory: `backend`
- Build Command: `npm install`
- Start Command: `npm start`
- Health Check Path: `/api/health`
- Runtime: Node 20 or newer

Configure these environment variables in Render Dashboard (never in Git):

- `NODE_ENV=production`
- `SESSION_SECRET`: at least 32 random characters; generated by Blueprint if supported
- `SESSION_COOKIE_NAME=promiden.sid`
- `SESSION_SAME_SITE=none` when the Vercel frontend and Render API are cross-site; use HTTPS only
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY` (server-only)
- `DATABASE_URL` (Supabase PostgreSQL session-pooler connection string, SSL enabled)
- `PAYSTACK_SECRET_KEY` (test key first)
- `APP_ORIGIN`: exact public frontend origin, e.g. `https://your-project.vercel.app`, no trailing slash
- `FRONTEND_ORIGIN`: same exact Vercel origin, no trailing slash

`APP_ORIGIN` is also used for the Paystack callback URL (`/payment.html`). After attaching a custom domain, update both origin variables to the chosen canonical frontend origin and redeploy.

## Vercel frontend

Create a Vercel project linked to the same repository:

- Root Directory: `frontend`
- Framework Preset: Other
- Build Command: leave empty (static HTML/CSS/JS)
- Output Directory: `.` if the dashboard requires an explicit directory

Before deployment, edit `frontend/scripts/runtime-config.js` and set `window.PROMIDEN_API_BASE` to the Render service URL, e.g. `https://promiden-pharma-api.onrender.com` (no trailing slash). This value is public and must never contain secrets. Redeploy the frontend after changing it.

## Important session-cookie caveat

Separate Vercel and `onrender.com` hostnames are cross-site for browser cookies; some browsers/privacy settings may block cross-site session cookies even with `SameSite=None; Secure`. For reliable admin sessions, the recommended production topology is custom domains under the same registrable domain, such as `www.example.com` for Vercel and `api.example.com` for Render. Set `APP_ORIGIN` and `FRONTEND_ORIGIN` to the frontend origin. Do not loosen CORS to `*` when credentials are enabled.

## First push and deployment sequence

1. Create a private GitHub repository and push this project root.
2. Wait for the GitHub Actions backend syntax check to pass.
3. Apply and verify the M06 Supabase migration in the intended environment.
4. Deploy the Render backend with test credentials and exact origins.
5. Check `https://YOUR-RENDER-SERVICE.onrender.com/api/health` returns HTTP 200.
6. Configure `frontend/scripts/runtime-config.js` with the Render API URL and deploy the `frontend/` root to Vercel.
7. Test admin login/session, public catalogue, order creation, test checkout, payment verification/webhooks, and the dashboard order list in a staging environment.
8. Use Paystack live credentials only after business/catalogue approval, staging verification, and security review.

## M10 API contract

- `GET /api/admin/orders?limit=25&offset=0&order_status=&payment_status=`
- `GET /api/admin/orders/:id`
- `PATCH /api/admin/orders/:id/status` with JSON `{ "orderStatus": "processing" | "fulfilled" | "cancelled" }`

All endpoints require an authenticated admin session and accepted request origin. The status endpoint deliberately does not accept `paymentStatus`.
